3일차: 스택(Stack), 큐(Queue), 덱(Deque) 정복

시간 복잡도 O(1)의 덱 활용법과 프로세스 스케줄링 시뮬레이션

📚 1. 스택 (Stack, LIFO - 후입선출)

나중에 들어온 데이터가 먼저 나가는 구조입니다. 파이썬에서는 기본 list의 append()와 pop()으로 완벽히 작동합니다.

# 괄호 짝 맞추기 (스택 대표 문제 패턴)
def is_valid_parentheses(s):
    stack = []
    bracket_map = {')': '(', '}': '{', ']': '['}
    
    for char in s:
        if char in "({[":
            stack.append(char)
        elif char in ")}]":
            if not stack or stack[-1] != bracket_map[char]:
                return False
            stack.pop()
            
    return len(stack) == 0

⚡ 2. 큐 (Queue, FIFO) vs 덱 (Deque) 및 시간복잡도

⚠️ 주의: 코테에서 list.pop(0) 절대 금지!

파이썬 list.pop(0)은 첫 요소를 삭제한 뒤 남은 $N$개의 요소를 모두 한 칸씩 앞으로 당기기 때문에 $O(N)$ 시간이 소요되어 시간 초과가 발생합니다.
반면 collections.deque.popleft()는 $O(1)$ 시간에 처리됩니다.

구분 파이썬 list.pop(0) collections.deque.popleft()
시간 복잡도 O(N) (10만 개 탐색 시 ~0.5초) O(1) (10만 개 탐색 시 ~0.003초)
내부 구조 동적 배열 (Array) 이중 연결 리스트 (Doubly Linked List) 
from collections import deque

dq = deque([1, 2, 3, 4, 5])

# 1. 양방향 데이터 입출력 (O(1))
dq.append(6)       # 오른쪽 추가
dq.appendleft(0)   # 왼쪽 추가
dq.pop()           # 오른쪽 제거
dq.popleft()       # 왼쪽 제거

# 2. 덱 회전 (rotate)
dq.rotate(2)   # 오른쪽 2칸 회전
dq.rotate(-2)  # 왼쪽 2칸 회전

📝 3. [실습 문제 3] 큐 기반 프로세스 스케줄링 시뮬레이션

문제: 프로세스 우선순위 큐에서 가장 앞의 프로세스를 꺼내어 남아있는 큐에 더 높은 우선순위가 있으면 맨 뒤로 보냅니다. 지정된 location의 프로세스가 몇 번째로 실행되는지 구하세요.

from collections import deque

def solution(priorities, location):
    # (우선순위, 원래인덱스) 튜플을 큐에 저장
    queue = deque([(priority, i) for i, priority in enumerate(priorities)])
    execution_order = 0
    
    while queue:
        current = queue.popleft()
        
        # 남아있는 큐에 더 높은 우선순위가 있는지 검사
        if any(current[0] < item[0] for item in queue):
            queue.append(current)  # 뒤로 회전
        else:
            execution_order += 1
            if current[1] == location:
                return execution_order
